# AperolSpritz — измеритель длины игл на ESP32-C3

AperolSpritz — автоматический измеритель длины игл на базе ESP32-C3 и шагового двигателя с драйвером TMC2209.

Устройство поддерживает ручное и автоматическое измерение, ручную и автоматическую калибровку, Web UI, сохранение настроек в NVS, сервисную калибровку перемещения в миллиметрах, аварийный STOP, световую и звуковую индикацию.

---

# 1. Как пользоваться

## 1.1. Перед первым использованием

Перед началом работы:

1. Убедитесь, что каретка свободно перемещается и механически не упирается в край хода.
2. Убедитесь, что `CONTACT` в исходном положении разомкнут.
3. Убедитесь, что кнопка `STOP` не нажата.
4. Проверьте работу оптического датчика иглы:
   - игла установлена → `NEEDLE = LOW`;
   - игла отсутствует → `NEEDLE = HIGH`.
5. Подключитесь к Web UI.
6. Проверьте настройки оператора:
   - номинальную длину;
   - допуск;
   - длину ручного калибра;
   - длину автокалибра;
   - расстояние отъезда;
   - направление движения (`Инвертировать DIR`).
7. При необходимости сначала откалибруйте масштаб перемещения в сервисном разделе.
8. Выполните калибровку устройства.

> После изменения `mm_per_step`, длины ручного/автоматического калибра или направления DIR текущая метрологическая калибровка становится недействительной. После таких изменений нужно выполнить калибровку заново.

# 2. Web-интерфейс

После подключения ESP32-C3 к сети откройте в браузере (IP-адрес указан на шаговом двигателе):

```text
http://<IP-адрес устройства>/
```

Интерфейс показывает:

- последнее измерение;
- отклонение от номинала;
- номинальную длину;
- допуск;
- цветовую оценку результата;
- состояние иглы;
- состояние CONTACT;
- состояние STOP;
- текущую ошибку;
- режим Wi-Fi и IP;
- текущую фазу FSM;
- состояние автоматического режима;
- тип и опорную длину последней калибровки;
- количество измерений после калибровки;
- сервисную калибровку перемещения.

### Цвет результата

В Web UI используется следующая индикация:

- **зелёный** — результат находится в допуске и не ближе 80% допуска к его границе;
- **жёлтый** — результат ещё в допуске, но отклонение достигло не менее 80% допуска;
- **красный** — результат вышел за допуск;
- **серый** — измерения ещё не было.

# 3. Ручной режим

## 3.1. Ручная калибровка

Ручная калибровка задаёт точку отсчёта для последующих измерений.

Перед калибровкой:

- `STOP` должен быть неактивен;
- `CONTACT` должен быть свободен;
- автоматический режим должен быть выключен;
- в настройках должна быть указана фактическая длина ручного калибра.

Калибровку можно запустить:

- кнопкой `CALIBRATE`;
- кнопкой **Калибровать** в Web UI.

Оптический датчик `NEEDLE` при ручной калибровке не используется.

Последовательность:

```text
быстрый подход
    ↓
CONTACT
    ↓
отъезд
    ↓
медленный точный подход
    ↓
CONTACT
    ↓
финальный отъезд
    ↓
готово
```

В качестве калибровочной координаты сохраняется только точка второго, медленного касания.

После успешной калибровки устройство запоминает:

- координату точного CONTACT;
- длину использованного калибра;
- тип калибровки `MANUAL`.

---

## 3.2. Ручное измерение

Перед измерением должны выполняться условия:

- устройство откалибровано;
- игла обнаружена оптическим датчиком;
- `CONTACT` в исходном положении свободен;
- `STOP` неактивен.

Измерение можно запустить:

- кнопкой `MEASURE`;
- кнопкой **Измерить** в Web UI.

Алгоритм такой же двухпроходный:

```text
быстрый подход
    ↓
CONTACT
    ↓
отъезд
    ↓
медленный точный подход
    ↓
CONTACT
    ↓
финальный отъезд
    ↓
результат
```

Итоговая длина определяется по координате второго касания.

После точного касания в `MEASURE_FINE` результат уже зафиксирован, поэтому во время финального отъезда иглу можно снимать.

# 4. Автоматический режим

Автоматический режим предназначен для циклической работы без запуска каждого измерения вручную.

Включается кнопкой:

```text
Авто: ВКЛ
```

в Web UI.

Автоматический цикл:

```text
ожидание иглы
    ↓
игла установлена
    ↓
автоматическое измерение
    ↓
ожидание снятия иглы
    ↓
игла снята
    ↓
автокалибровка
    ↓
возврат каретки в загрузочную позицию
    ↓
ожидание освобождения оптического датчика
    ↓
ожидание следующей иглы
```

В автоматическом режиме оптический датчик используется для определения установки и снятия иглы.

Во время самой автокалибровки и возврата каретки ложные перекрытия оптического датчика не должны запускать новое измерение. Новая игла принимается только после того, как датчик сначала устойчиво подтвердил свободное состояние.

Автоматический режим выключается при:

- STOP;
- ошибке;
- ручной команде остановки AUTO.

После перезагрузки автоматический режим не считается включённым.

# 5. Световая и звуковая индикация

## Буззер (Динамик)

Текущая прошивка использует активный буззер на `GPIO8`.

Сигналы:

- короткий писк — началось измерение;
- короткий писк — началась калибровка;
- более длинный писк — операция успешно завершена и устройство снова перешло в ожидание;
- три коротких прерывистых сигнала — возникла ошибка.

Сервисное перемещение не использует обычные сигналы измерения/калибровки.

Параметры звука находятся в:

```text
main/config/indicator_config.hpp
```

Основные параметры:

```cpp
BUZZER_START_MS
BUZZER_SUCCESS_MS
BUZZER_ERROR_ON_MS
BUZZER_ERROR_OFF_MS
BUZZER_ERROR_COUNT
BUZZER_INVERTED
```

## Светодиод

Статусный светодиод подключён к `GPIO9`.

Логика:

| Состояние | LED |
|---|---|
| Ожидание | выключен |
| Измерение | горит |
| Калибровка | горит |
| Возврат / JOG / сервисное движение | горит |
| ERROR | мигает |
| STOP | выключен |

В текущей конфигурации:

```cpp
STATUS_LED_INVERTED = true;
```

То есть логическое включение LED соответствует низкому уровню на GPIO9.

# 6. STOP и ошибки

## STOP

`STOP` имеет максимальный приоритет.

При его срабатывании:

- STEP немедленно прекращается;
- TMC2209 отключается через `EN`;
- автоматический режим выключается;
- текущий звук прекращается;
- FSM переходит в `STOPPED`.

После физического освобождения кнопки STOP нужно выполнить:

```text
Сброс STOP
```

в Web UI.

## Ошибки

При ошибке:

- двигатель останавливается;
- автоматический режим выключается;
- статусный LED начинает мигать;
- буззер один раз воспроизводит прерывистый аварийный сигнал;
- устройство остаётся в `ERROR`.

После устранения причины нажмите:

```text
Сброс ошибки
```

Основные ошибки:

| Ошибка | Значение |
|---|---|
| `NEEDLE_NOT_FOUND` | игла не обнаружена или исчезла во время измерения |
| `CONTACT_ALREADY_ACTIVE` | CONTACT уже замкнут до начала операции |
| `CONTACT_RELEASE_TIMEOUT` | после отъезда CONTACT не освободился |
| `MEASUREMENT_TIMEOUT` | превышено максимальное время измерения |
| `CALIBRATION_TIMEOUT` | превышено максимальное время калибровки |
| `MAX_STEPS_REACHED` | достигнут лимит перемещения |
| `NOT_CALIBRATED` | попытка измерения без действующей калибровки |
| `STOP_ACTIVE` | активен STOP |
| `INVALID_CONFIG` | некорректные параметры |
| `INTERNAL_ERROR` | внутренняя ошибка или остановка движения |

# 7. Ручной отъезд LEFT / JOG

Кнопка `LEFT` используется для ручного движения каретки от измерительного контакта.

Пока кнопка удерживается:

```text
каретка движется влево / от CONTACT
```

После отпускания движение прекращается.

JOG доступен только вне автоматического режима.

Активный CONTACT не запрещает движение от него.

# 8. Калибровка перемещения и mm_per_step

В нижней части Web UI расположен сервисный раздел:

```text
Калибровка перемещения
```

Он предназначен для настройки коэффициента:

```text
mm_per_step
```

то есть фактического линейного перемещения каретки на один импульс STEP.

Сервисное движение доступно только когда:

- FSM находится в `IDLE`;
- AUTO выключен;
- STOP неактивен;
- нет ошибки;
- мотор не выполняет другое движение.

Максимальная команда:

```text
±150 мм
```

Знак задаёт направление:

```text
-100 мм → влево
+100 мм → вправо
```

Если CONTACT уже активен, разрешается только движение от контакта.

## Порядок калибровки

1. Введите известное перемещение, например:

```text
-100.000 мм
```

2. Нажмите **Переместить**.
3. Измерьте реальный ход каретки.
4. Введите фактическое перемещение положительным числом, например:

```text
99.720 мм
```

5. Нажмите **Рассчитать**.

Web UI вычислит:

```text
ошибку в мм
ошибку в %
новый mm_per_step
новое количество шагов на мм
```

Используется формула:

```text
new_mm_per_step =
    old_mm_per_step × actual_distance / commanded_distance
```

6. Нажмите **Применить коэффициент**.
7. Подтвердите изменение.
8. Повторите тестовое перемещение.
9. После настройки обязательно выполните новую калибровку измерителя.

`mm_per_step` сохраняется в NVS и используется всеми преобразованиями миллиметров в шаги и обратно.

> Устройство не имеет абсолютного HOME. Перед сервисным движением оператор обязан убедиться, что каретке хватает свободного механического хода.

# 9. Настройки оператора

Через Web UI изменяются:

| Параметр | Назначение |
|---|---|
| Номинальная длина | размер, относительно которого рассчитывается отклонение |
| Допуск | допустимое абсолютное отклонение |
| Длина ручного калибра | известная длина при ручной калибровке |
| Длина автокалибра | известная длина встроенного автоматического калибра |
| Расстояние отъезда | ход каретки после касания CONTACT |
| Инвертировать DIR | меняет физическое направление подхода |

`mm_per_step` не редактируется в обычном блоке настроек. Он изменяется только через сервисную калибровку перемещения.

# 10. Как считается длина

Устройство хранит знаковую программную координату:

```text
position_steps
```

Она изменяется на каждом реально сформированном импульсе STEP.

Во время калибровки запоминается координата:

```text
calibration_contact_position_steps
```

Во время измерения:

```text
measurement_contact_position_steps
```

Расчёт основан на разности координат:

```text
L =
    calibration_reference_length_mm
    + direction_sign
    × (calibration_position - measurement_position)
    × mm_per_step
```

Направление автоматически учитывает параметр `measure_dir_inverted`.

`position_steps` является относительной программной координатой.

Она остаётся корректной только пока:

- двигатель не пропускает шаги;
- каретка не перемещается вручную при отключённом приводе;
- механика не проскальзывает.

Абсолютного HOME-датчика в текущей конструкции нет.

# 11. Алгоритм CONTACT

CONTACT — отдельный измерительный вход.

Логика:

```text
HIGH = свободен
LOW  = контакт замкнут
```

При первом переходе CONTACT в LOW генерация STEP останавливается максимально быстро.

После этого контроллер подтверждает уровень с коротким debounce. Если импульс оказался дребезгом и CONTACT снова стал HIGH, текущее движение продолжается без сброса программной координаты.

В итоговую калибровку и измерение используется только точка второго, медленного касания.

# 12. Подключение электроники

Текущая прошивка рассчитана на ESP32-C3 и драйвер TMC2209 в режиме STEP/DIR/EN.

UART-интерфейс TMC2209 прошивкой не используется.

## GPIO

| GPIO | Сигнал | Тип | Логика |
|---:|---|---|---|
| 0 | `STOP` | вход | LOW — аварийная остановка |
| 1 | `LEFT` | вход | LOW — ручной отъезд |
| 2 | `CALIBRATE` | вход | LOW — ручная калибровка |
| 3 | `CONTACT` | вход | LOW — контакт замкнут |
| 4 | `NEEDLE` | вход | LOW — игла есть, HIGH — иглы нет |
| 5 | `DIR` | выход | направление TMC2209 |
| 6 | `STEP` | выход | импульсы TMC2209 |
| 7 | `EN` | выход | LOW — драйвер включён |
| 8 | `BUZZER` | выход | звуковая индикация |
| 9 | `STATUS_LED` | выход | статусный LED, по умолчанию active-low |
| 10 | `MEASURE` | вход | LOW — ручное измерение |

### Кнопки

`STOP`, `LEFT`, `CALIBRATE`, `MEASURE` и `CONTACT` настроены как active-low входы с внутренней подтяжкой вверх.

Для обычной кнопки:

```text
GPIO ─── кнопка ─── GND
```

### Оптический датчик NEEDLE

GPIO4 не использует внутреннюю подтяжку.

Датчик должен сам формировать цифровой уровень:

```text
датчик OUT → GPIO4
датчик GND → общий GND
```

Логика текущей прошивки:

```text
LOW  = игла обнаружена
HIGH = игла отсутствует
```

Выход датчика должен быть совместим с логическими уровнями ESP32-C3.

### CONTACT

CONTACT электрически независим от оптического датчика.

Контакт должен замыкать GPIO3 на GND:

```text
GPIO3 ─── CONTACT ─── GND
```

### TMC2209

Минимальные управляющие сигналы:

```text
GPIO5 → DIR
GPIO6 → STEP
GPIO7 → EN
GND   → GND драйвера
```

`EN` активен низким уровнем.

Питание двигателя, ток драйвера и микрошаг должны быть настроены в соответствии с конкретным двигателем, драйвером и механикой. Эти параметры прошивка не конфигурирует.

### Буззер

Текущая прошивка:

```text
GPIO8 → BUZZER
```

`BUZZER_INVERTED = false`.

Если используется активный буззер в текущей прототипной схеме:

```text
GPIO8 → (+) buzzer
GND   → (-) buzzer
```

Если конкретный буззер требует ток выше допустимого для GPIO, его нужно подключать через транзисторный ключ.

### Статусный LED

Текущая прошивка использует active-low LED:

```text
3.3 V
  │
резистор
  │
 LED
  │
GPIO9
```

По умолчанию:

```text
GPIO9 LOW  → LED ON
GPIO9 HIGH → LED OFF
```

# 13. Важное замечание по GPIO2, GPIO8 и GPIO9

GPIO2, GPIO8 и GPIO9 у ESP32-C3 являются strapping-пинами и считываются во время reset.

В текущей распиновке на них находятся:

```text
GPIO2 → CALIBRATE
GPIO8 → BUZZER
GPIO9 → STATUS_LED
```

Поэтому внешняя схема не должна принудительно формировать неправильные уровни на этих выводах во время загрузки.

В частности:

- не удерживайте `CALIBRATE` нажатой при включении/сбросе;
- не допускайте сильной внешней подтяжки GPIO9 к GND во время reset;
- не устанавливайте большую ёмкость на GPIO9;
- при проблемах с загрузкой сначала отключите внешние цепи GPIO2/GPIO8/GPIO9 и проверьте старт ESP32-C3.

# 14. Wi-Fi

Прошивка поддерживает:

- WPA2-PSK;
- WPA2-Enterprise / PEAP;
- автоматический fallback Access Point.

## Настройка STA

Скопируйте:

```text
secrets.example.txt
```

в:

```text
secrets.txt
```

и укажите реальные параметры сети.

> `secrets.txt` содержит пароль. Не добавляйте этот файл в Git!!!

### WPA2-PSK

```text
WIFI_AUTH=psk
WIFI_SSID=YOUR_SSID
WIFI_PASSWORD=YOUR_PASSWORD
```

### WPA2-Enterprise / PEAP

```text
WIFI_AUTH=enterprise
WIFI_SSID=YOUR_SSID
WIFI_IDENTITY=YOUR_IDENTITY
WIFI_USERNAME=YOUR_USERNAME
WIFI_PASSWORD=YOUR_PASSWORD
```

Во время сборки `secrets.txt` преобразуется CMake в заголовочный файл внутри build directory.

Пароль не отдаётся через Web UI или REST API.

## Fallback AP

Если credentials отсутствуют, некорректны или устройство не подключилось к STA за время ожидания, запускается точка доступа:

```text
SSID:     NeedleMeter
Password: NeedleMeter2026
IP:       192.168.4.1
```

После подключения откройте:

```text
http://192.168.4.1/
```

Если STA-соединение было установлено, но затем потеряно, прошивка пытается переподключиться.

Физические кнопки и измерительная FSM не зависят от доступности Wi-Fi.

Начальное значение масштаба:

```text
DEFAULT_MM_PER_STEP = 0.0003127
```

Рабочий `mm_per_step` хранится в `DeviceConfig` и NVS.

# 17. REST API

Web UI использует тот же REST API.

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/api/status` | текущее состояние |
| GET | `/api/config` | текущая конфигурация |
| POST | `/api/config` | сохранить настройки оператора |
| POST | `/api/measure` | начать измерение |
| POST | `/api/calibrate` | начать ручную калибровку |
| POST | `/api/auto/start` | включить AUTO |
| POST | `/api/auto/stop` | выключить AUTO |
| POST | `/api/stop` | программный STOP |
| POST | `/api/reset-stop` | сбросить STOP |
| POST | `/api/reset-error` | сбросить ERROR |
| POST | `/api/factory-reset` | сбросить NVS к значениям по умолчанию |
| POST | `/api/service-move` | сервисное перемещение в мм |
| POST | `/api/service/mm-per-step` | сохранить новый коэффициент mm/step |

Пример сервисного перемещения:

```json
{
  "distance_mm": -100.0
}
```

# 18. Хранение конфигурации

Настройки и статистика сохраняются в NVS namespace:

```text
needle_meter
```

В NVS сохраняются, в частности:

- настройки оператора;
- `mm_per_step`;
- последняя действующая калибровка;
- тип калибровки;
- координата калибровочного CONTACT;
- последнее измерение;
- счётчики измерений и калибровок.

Текущая версия структуры конфигурации:

```text
CONFIG_VERSION = 5
```

При обновлении с версии 4 настройки оператора мигрируют в v5, а новый `mm_per_step` получает значение по умолчанию.

```text
Browser
   │
   ▼
WebServer
   │
   ▼

   │
```
