# AperolSpritz Desktop

Обычное Windows-приложение на `tkinter + ttk` для полного управления измерителями
AperolSpritz без браузера. Оно одновременно опрашивает несколько ESP32, сохраняет
новые измерения в SQLite и позволяет управлять выбранной установкой через штатный
REST API прошивки.

## Начало работы

1. В группе **Устройство** нажмите **Добавить**.
2. Введите понятное имя установки и её IP без пути, например `10.0.8.100`.
3. Добавьте остальные установки. Выбор в списке определяет только цель команд;
   мониторинг и запись истории продолжаются для всех добавленных устройств.
4. Зелёная надпись **Подключено** означает, что от выбранного устройства получен
   актуальный `/api/status`. При потере связи Desktop не показывает старое
   состояние как текущее и автоматически продолжает попытки подключения.

## Вкладка «Работа»

- **Измерить** запускает ручное измерение.
- **Калибровать** запускает ручную метрологическую калибровку.
- **Включить авто / Выключить авто** отражает фактическое состояние AUTO на ESP32.
  Обычное выключение AUTO выполняется безопасной командой, а не STOP.
- **STOP** доступен всегда, пока устройство находится на связи. Это программная
  команда с отдельным коротким сетевым путём; физическая кнопка STOP остаётся
  основным аварийным средством.
- **Сброс STOP** и **Сброс ошибки** становятся доступны в соответствующих состояниях.

Результат классифицируется как в Web UI: зелёный — в допуске, жёлтый — от 80% до
границы допуска, красный — вне допуска. Для классификации используются исходные
значения без предварительного округления.

## Вкладка «Настройки»

Настройки загружаются с выбранной ESP32 через `GET /api/config`. Доступны номинал,
допуск, длины ручного и автоматического калибров, отъезд, интервал автокалибровки
и инверсия DIR. **Сохранить настройки** отправляет полный операторский объект в
`POST /api/config`. Переключение вкладки само ничего не сохраняет. При смене
устройства Desktop предупреждает о несохранённых изменениях.

Прошивка самостоятельно решает, приводит ли изменение к сбросу действительности
калибровки. Desktop показывает последующее состояние из `/api/status`.

## Вкладка «Сервис»

**Переместить** отправляет миллиметры в `POST /api/service-move`; шаги рассчитывает
ESP32 по своему актуальному `mm_per_step`. Отрицательное значение означает движение
влево, положительное — вправо. Перед большим перемещением требуется подтверждение,
поскольку абсолютной HOME-позиции и программных механических координат нет.

Для коррекции коэффициента:

1. Выполните известное сервисное перемещение.
2. Измерьте фактическое расстояние и введите положительное значение.
3. Нажмите **Рассчитать**.
4. Проверьте старое и новое значения и нажмите **Применить коэффициент**.
5. Выполните новую метрологическую калибровку.

Формула совпадает с Web UI: `new = old * actual / abs(commanded)`. Применение идёт
через `POST /api/service/mm-per-step`; отдельная локальная копия коэффициента не
хранится. **Сбросить настройки устройства** использует двойное подтверждение и
`POST /api/factory-reset`. Локальная история при этом не удаляется.

## История и экспорт

Каждое устройство опрашивается собственным worker-потоком. Новые события из
`GET /api/measurements` сохраняются в SQLite с исходными `device_id`, `boot_id` и
`measurement_seq`; их уникальность обеспечивает прежнюю дедупликацию. Heartbeat
для Web UI также продолжает отправляться. При переполнении буфера ESP32 выводится
предупреждение о возможном пропуске.

**Экспорт Excel** и **Экспорт CSV** читают всю SQLite, а не только 200 видимых строк.
CSV использует UTF-8 с BOM и разделитель `;`.

Пользовательские данные находятся вне каталога установки:

```text
%APPDATA%\AperolSpritz\settings.json
%APPDATA%\AperolSpritz\measurements.db
```

## Запуск и тесты

Требуется Python 3.9 или новее с `tkinter`.

```powershell
cd desktop
python -m pip install -r requirements.txt -r requirements-build.txt
python -m compileall -q app.py aperolspritz tests
python -m pytest -q
python app.py
```

Тесты используют поддельные HTTP-ответы и никогда не отправляют команды реальной
установке.

## Windows-сборка

```powershell
cd desktop
.\build.ps1
.\scripts\smoke_test_frozen.ps1
```

Скрипт создаёт onedir-сборку `dist\AperolSpritz\AperolSpritz.exe`. Не переносите
EXE отдельно от `_internal`. Frozen smoke test запускает настоящий GUI с временным
`APPDATA` и не требует доступной ESP32.

Единственный источник версии — [`VERSION`](VERSION). Публикация GitHub Release и
создание тега выполняются отдельно; существующий релиз `v1.0.0` не изменяется.

## Если устройство недоступно

- проверьте IP и доступность `http://<IP>/` в той же сети;
- проверьте firewall для локальных HTTP-запросов;
- дождитесь автоматического восстановления связи.

Недоступность одной установки не блокирует остальные и не замораживает GUI.
