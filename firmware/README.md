# Прошивка AperolSpritz

Прошивка управляет измерителем длины игл на ESP32-C3: шаговым двигателем через
TMC2209, контактным и оптическим датчиками, физическими кнопками, индикацией,
Web UI и REST API. Настройки и метрологическая статистика сохраняются в NVS.

## Аппаратная платформа

- плата: `esp32-c3-devkitm-1`;
- framework: ESP-IDF через PlatformIO;
- драйвер двигателя: TMC2209 в режиме STEP/DIR/EN;
- последовательный монитор: 115200 бод.

Источник назначений выводов — [`main/config/pins.hpp`](main/config/pins.hpp).

| GPIO | Сигнал | Направление | Активный уровень / назначение |
|---:|---|---|---|
| 0 | `STOP` | вход | LOW, аварийная остановка |
| 1 | `LEFT` | вход | LOW, ручное движение от CONTACT |
| 2 | `CALIBRATE` | вход | LOW, ручная калибровка |
| 3 | `CONTACT` | вход | LOW, механический контакт |
| 4 | `NEEDLE` | вход | LOW, игла присутствует |
| 5 | `DIR` | выход | направление TMC2209 |
| 6 | `STEP` | выход | импульсы TMC2209 |
| 7 | `EN` | выход | LOW включает TMC2209 |
| 8 | `BUZZER` | выход | активный буззер |
| 9 | `STATUS_LED` | выход | инверсный, LOW включает LED |
| 10 | `MEASURE` | вход | LOW, ручное измерение |

Кнопки `STOP`, `LEFT`, `CALIBRATE`, `MEASURE` и контакт `CONTACT` замыкают
соответствующий GPIO на GND; для них включена внутренняя подтяжка вверх. Выход
оптического датчика подключается к GPIO4 и должен сам формировать уровни: внутренняя
подтяжка на этом входе отключена. Общая земля датчиков, ESP32 и драйвера обязательна.
Если буззеру требуется ток выше допустимого для GPIO, используйте транзисторный ключ.

GPIO2, GPIO8 и GPIO9 — strapping pins ESP32-C3. Внешние цепи не должны задавать
неподходящие уровни во время reset; особенно нельзя сильно удерживать GPIO9 в LOW.
При проблемах загрузки сначала отключите цепи этих трёх выводов и проверьте старт.

## Режимы измерения и калибровки

Ручное измерение запускается кнопкой `MEASURE` или `POST /api/measure`. Требуются
действующая калибровка, установленная игла, свободный CONTACT и неактивный STOP.
Ручная калибровка запускается `CALIBRATE` или `POST /api/calibrate`; длина эталона
берётся из `calibration_length_mm`, а оптический датчик иглы не используется.

Измерение и калибровка используют двухпроходный алгоритм:

```text
быстрый подход → CONTACT → отъезд → медленный подход → CONTACT → финальный отъезд
```

Координатой результата является второе, медленное касание. `CONTACT` останавливает
подход на аппаратно обслуживаемом событии. До старта операции он должен быть
свободен; после отъезда обязан освободиться за заданный тайм-аут.

`NEEDLE` подтверждает наличие иглы в ручном и автоматическом измерении. LOW означает
«игла установлена», HIGH — «игла отсутствует». Исчезновение иглы во время критической
части измерения приводит к ошибке `NEEDLE_NOT_FOUND`.

## Автоматический режим

AUTO включается и выключается через Web UI или `/api/auto/start` и
`/api/auto/stop`. Цикл ожидает иглу, измеряет её, ожидает снятия и при достижении
интервала выполняет автокалибровку по `auto_calibration_length_mm`. После этого
каретка возвращается к загрузочной позиции и принимает следующую иглу только после
устойчивого свободного состояния оптического датчика.

`auto_calibration_interval` принимает `1..1000`; считаются только успешные AUTO-
измерения, а успешная калибровка сбрасывает счётчик. Отключение AUTO во время
движения — graceful stop после безопасной последовательности. STOP прекращает
движение немедленно и отключает драйвер.

## Движение и `mm_per_step`

Фактические пределы и скорости находятся в
[`main/config/motion_config.hpp`](main/config/motion_config.hpp):

| Параметр | Значение |
|---|---:|
| `DEFAULT_MM_PER_STEP` | `0.0003127` мм/шаг |
| быстрый подход | 1500 шаг/с |
| точный подход | 500 шаг/с |
| retract | 1500 шаг/с |
| JOG / service / AUTO load | 4000 шаг/с |
| ускорение | 4000 шаг/с² |
| максимум измерения / калибровки | 75 мм |
| максимум retract | 20 мм |
| максимум service move | 150 мм |
| AUTO load position | 182 мм |

Сервисный раздел Web UI перемещает каретку на известное расстояние и вычисляет:

```text
new_mm_per_step = old_mm_per_step × actual_distance / commanded_distance
```

Коэффициент сохраняется в NVS. Его изменение, изменение длины калибра или направления
DIR отменяет действующую метрологическую калибровку. Абсолютного HOME нет: перед
сервисным движением оператор должен проверить доступный механический ход.

## Индикация

Настройки находятся в
[`main/config/indicator_config.hpp`](main/config/indicator_config.hpp).

- короткий сигнал 60 мс — старт измерения;
- сигнал 1000 мс — предупреждение перед калибровочным движением;
- сигнал 180 мс — успешное завершение;
- три импульса 80/90 мс — ошибка;
- LED горит при движении, мигает каждые 250 мс в ERROR и выключен в ожидании/STOP.

`BUZZER_INVERTED = false`, `STATUS_LED_INVERTED = true`.

## Wi-Fi

Скопируйте пример и заполните локальные реквизиты:

```powershell
cd firmware
Copy-Item secrets.example.txt secrets.txt
```

Поддерживаются `WIFI_AUTH=psk` и WPA2-Enterprise/PEAP с
`WIFI_AUTH=enterprise`, `WIFI_IDENTITY`, `WIFI_USERNAME`, `WIFI_PASSWORD`.
`secrets.txt` игнорируется Git; не добавляйте в коммиты реальные SSID, логины и
пароли. CMake генерирует заголовок только в каталоге сборки.

Если реквизиты отсутствуют, неполны или подключение не установлено за 12 секунд,
прошивка запускает fallback AP `NeedleMeter`. Текущий режим и IP видны в Web UI и
`GET /api/status`.

## Сборка и прошивка

Установите PlatformIO, затем из корня репозитория выполните:

```powershell
cd firmware
pio run
pio run -t upload
pio device monitor -b 115200
```

Команды соответствуют окружению `[env:esp32-c3-devkitm-1]` в
[`platformio.ini`](platformio.ini). Проект использует ESP-IDF, а
`sdkconfig.defaults` передаётся как файл начальной конфигурации.

## NVS

Конфигурация и статистика хранятся в namespace `needle_meter` в blob-ключах
`config` и `stats`. Текущая схема — версия 6; код сохраняет миграцию конфигурации
v4/v5 и статистики v5. В частности, сохраняются длины калибров, номинал, допуск,
retract, направление, `mm_per_step`, интервал AUTO, координаты и счётчики.

`POST /api/factory-reset` очищает только namespace приложения и возвращает значения
по умолчанию. Runtime ring buffer измерений и heartbeat desktop во flash не пишутся.

## REST API

Web UI использует тот же HTTP API:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | Web UI |
| GET | `/api/status` | состояние FSM, датчиков, Wi-Fi и последнего результата |
| GET | `/api/config` | настройки оператора |
| POST | `/api/config` | изменить обычные настройки в IDLE |
| GET | `/api/measurements?after_seq=N` | события из RAM ring buffer после sequence |
| POST | `/api/logger/heartbeat` | heartbeat desktop-приложения |
| POST | `/api/measure` | ручное измерение |
| POST | `/api/calibrate` | ручная калибровка |
| POST | `/api/auto/start` | включить AUTO |
| POST | `/api/auto/stop` | запросить выключение AUTO |
| POST | `/api/stop` | программный STOP |
| POST | `/api/reset-stop` | сбросить STOP после освобождения кнопки |
| POST | `/api/reset-error` | сбросить ERROR |
| POST | `/api/factory-reset` | сбросить NVS |
| POST | `/api/service-move` | сервисное перемещение (`distance_mm`) |
| POST | `/api/service/mm-per-step` | сохранить коэффициент и отменить калибровку |

История устройства содержит максимум 32 события. Desktop дедуплицирует их по
`(device_id, boot_id, measurement_seq)`; `history_gap=true` означает, что часть
запрошенных событий уже вытеснена из RAM.

## Состояния FSM

Основные состояния определены в
[`main/measurement/measurement_controller.hpp`](main/measurement/measurement_controller.hpp):

- `IDLE` — ожидание;
- `MEASURE_*` — быстрый проход, retract, точный проход и финальный retract;
- `CALIBRATE_*` — ручная/автоматическая калибровочная последовательность;
- `AUTO_WAIT_SENSOR_CLEAR`, `AUTO_WAIT_NEEDLE`, `AUTO_WAIT_REMOVE` — ожидания AUTO;
- `AUTO_MOVE_TO_LOAD` — возврат к загрузочной позиции;
- `MANUAL_LEFT`, `SERVICE_MOVE` — ручное и сервисное движение;
- `FINISHED`, `STOPPED`, `ERROR` — завершение и защитные состояния.

Ошибки API и Web UI: `NEEDLE_NOT_FOUND`, `CONTACT_ALREADY_ACTIVE`,
`CONTACT_RELEASE_TIMEOUT`, `MEASUREMENT_TIMEOUT`, `CALIBRATION_TIMEOUT`,
`MAX_STEPS_REACHED`, `NOT_CALIBRATED`, `STOP_ACTIVE`, `INVALID_CONFIG` и
`INTERNAL_ERROR`.

## Диагностика и ограничения

- сначала проверьте STOP, свободный CONTACT, уровни NEEDLE и общую землю;
- при проблемах запуска ESP32 отключите внешние цепи strapping pins;
- по serial monitor проверяйте причины Wi-Fi disconnect и сообщения FSM;
- при `CONTACT_RELEASE_TIMEOUT` проверьте механику, проводку и расстояние retract;
- при `MAX_STEPS_REACHED` проверьте `mm_per_step`, направление и свободный ход;
- настройки разрешено менять только в `IDLE`;
- устройство не имеет абсолютного HOME и не определяет механические границы;
- REST API использует HTTP в локальной сети и не предназначен для публикации в
  интернет;
- отсутствие Wi-Fi не блокирует физические кнопки и локальный цикл измерения.

Основные источники истины: `pins.hpp`, `motion_config.hpp`,
`indicator_config.hpp`, `device_config.hpp`, `measurement_controller.*` и
`web/web_server.cpp`. При изменении прошивки документацию следует сверять с ними.
